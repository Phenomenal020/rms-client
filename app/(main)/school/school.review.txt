      slug: string;          // registration ID for teachers
      logo?: string | null;
      metadata?: {
        address?: string | null;
        motto?: string | null;
        telephone?: string | null;

      createdAt?: string;
    }
  Issues:

    • metadata not validated at client boundary — trust BA JSON shape 📌
    • Legacy commented schoolPayload in types/organisation.ts used different field names
      (schoolName, schoolRegistrationId) — migration residue

  Related GET (not used by SchoolForm but relevant to shell)

  UPDATE — authClient.organization.update({

    };
    organizationId: string;
  })
  • slug omitted from update payload — registration ID not editable
  FIX: Implemented ✅

  POST-CREATE — authClient.organization.setActive({ ... })
  • setActive failure shows toast.warning (partial success)
  FIX: Implemented ✅

Client Zod schema (organizationSchema in school-form.tsx)

  • Validates UI before submit — good first line of defence
  • id, slug in schema mostly unused on create (slug defaulted "autogenerate")
  • metadata optional at schema level; fields nullable — matches form UX

Backend mutation validation (auth-setup.ts Zod — source of truth)

  createOrgSchema
    name: trim, min 1, max 100
    metadata: orgMetadataSchema (optional)
    slug handled in beforeCreateOrganization hook, not in createOrgSchema input

  updateOrgSchema
    name: optional but min 1 if present, max 100

  orgMetadataSchema
    address max 255, motto max 500, telephone max 20, email nullable email
