  • Mutations used getErrorMessage only — no 401/403 redirect.
  • subjectsError destructured but never used.
  • No ErrorBanner or retry on load failure.
  • Fetch auth errors not redirected.

After fix (mirrors classes/students/teachers)
  • getApiErrorMessage + handleAuthRedirect on create/update mutations ✅

  • subjectsError → ErrorBanner with retryAllFetches (mutate /api/v1/subjects) ✅
  • useEffect 401/403 redirect on fetch errors (no toast on fetch) ✅
  • Search/add/edit disabled when loadError !== undefined || isComponentLoading ✅

  | Scenario                         | Client behaviour                  |
  |----------------------------------|-----------------------------------|
  | GET /subjects fail               | ErrorBanner + retry               | ✅
  | Empty org (success, [])          | Dashed empty state                | ✅

  | Create duplicate name (client)   | Toast before API                  | ✅
  | Update 404 subject not found     | Toast from API message            | ✅
  | Mutation 401/403                 | handleAuthRedirect + toast        | ✅
  | Mutation 500                     | Generic fallback toast            | ✅

Backend mitigation
  • OrgAdminGuard on SubjectsController ✅
  • runWithDbContext wraps create/update for consistent 500 mapping ✅
  • PATCH WHERE includes organizationId — cross-org id returns 404 ✅
  📌 Return 409 on duplicate name at DB/ service layer
  📌 Remove debug console.log from getSubjects

10) MUTATION DTOs
--------------------------------------------------------------------------------

  createSubjectPayload — POST /api/v1/subjects
    Request: { name: string; department: string }
    Server: CreateSubjectDto (@IsString, @IsNotEmpty, @Transform trim)
    Response: { success: string; data: newSubject }
    Hook onSuccess: mutate('/api/v1/subjects') ✅

  updateSubjectPayload — PATCH /api/v1/subjects/:id
    Request: { id, name?, department? } — client sends all fields
    Server: UpdateSubjectDto + PatchSubjectParamsDto (UUID id)
    Response: { success: string; data: updated }
    Hook onSuccess: mutate('/api/v1/subjects') ✅

  Client zod
    department: z.enum(["none", "commerce", "science", "arts", "general"]) ✅
    Maps to createSubjectPayload.department string ✅

  Gaps
    📌 Add CreateSubjectResponse / UpdateSubjectResponse types
    📌 Server @IsIn for department enum parity with client
    📌 POST response includes full row for optimistic insert
