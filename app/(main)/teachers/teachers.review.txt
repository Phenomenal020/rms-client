2) API ISSUES (current + potential)
--------------------------------------------------------------------------------

Critical / high

  [Manual fetchMembers bypassed SWR cache]
    teachers-form called authClient.organization.listMembers in useEffect and
    stored results in local useState. Classes/enrollment reuse getOrgMembers()
    with ORG_MEMBERS_KEY — teachers route did not, so add/remove did not
    automatically refresh other pages using the same cache.
    FIX: Switched to getOrgMembers(); mutate(ORG_MEMBERS_KEY) after add/remove ✅

  [useAddMember had no cache invalidation]
    Comment said "caller re-fetches directly" but only manual fetchMembers() ran;
    no SWR invalidation for classes dropdowns.
    FIX: useAddMember onSuccess mutates ORG_MEMBERS_KEY ✅

  [listMembers failure silent]
    fetchMembers ignored error — empty teachers[] looked like "no teachers yet".
    FIX: membersError → ErrorBanner + retry ✅

  [Duplicate success toast on add]
    toast.success fired inside try and again after fetchMembers on success path.
    FIX: Single toast after successful mutation + cache revalidate ✅

  [Stale comment: teacher-invitation/add-member]
    Comment referenced old endpoint; actual mutation is
    POST /api/v1/organisation/add-member.
    FIX: Comments updated in review; code aligned ✅

  [removeMember uses email as memberIdOrEmail]
    Better Auth accepts email, but member id is more stable if email changes.
    teacherOption.id is available from listMembers — prefer memberId when BA
    exposes it on the list response.
    FIX: Using email is deliberate ✅

  [Add member requires pre-existing BA user account]
    organisation.service.addMember throws 404 if email not registered.
    UX depends on clear error message from NestJS — OK for admin flow.
    📌 Consider inviteMember flow for unregistered emails (email invite link)

Medium

  [Client-only duplicate email check]
    Local check before POST can race with concurrent admins.
    Backend should return 409 if member already in org.
    📌 BA addMember / custom guard should enforce uniqueness

  [listMembers returns all roles]
    Page title is "Teachers" but list includes orgadmin members too.
    getOrgMembers maps m.user only — member.role is dropped.
    📌 Filter role !== "orgadmin" or rename UI to "Staff" if intentional

  [No optimistic update on add/remove]
    Table waits for mutate revalidation. Acceptable; could optimistically
    append/remove row for snappier UX.
    📌 Optional enhancement

  [Removing orgadmin or self not blocked client-side]
    Could lock out the only admin or current session user.
    📌 Disable remove when teacher.id === user.id or role === orgadmin


3) ERROR HANDLING — 400, 500, client behaviour, backend mitigation
--------------------------------------------------------------------------------

Previous state
  • Add: catch (err: any) with err?.response?.data?.message only (axios shape).
  • Remove: generic toast on any BA error; no auth redirect.
  • Load: errors swallowed → false empty state.
  • No ErrorBanner or retry.

After fix (mirrors classes/students)
  • getApiErrorMessage + handleAuthRedirect on add/remove mutations ✅
  • membersError → ErrorBanner with retryAllFetches (mutate ORG_MEMBERS_KEY) ✅
  • useEffect 401/403 redirect on fetch errors (no toast on fetch) ✅
  • Buttons/search disabled when loadError !== undefined || isComponentLoading ✅

  | Scenario                         | Client behaviour                  |
  |----------------------------------|-----------------------------------|
  | listMembers fail                 | ErrorBanner + retry               | ✅
  | Empty org (success, [])          | Dashed empty state                | ✅
  | Add 404 (user not registered)    | Toast with NestJS message         | ✅
  | Add 400 (validation / BA fail)   | Toast via getApiErrorMessage      | ✅
  | Add 401/403                      | handleAuthRedirect + toast        | ✅
  | Add 500                          | Generic fallback toast            | ✅
  | Remove BA error                  | Toast; no silent failure          | ✅
  | Duplicate email (client)         | RHF setError on email field       | ✅

Backend mitigation
  • OrgAdminGuard on OrganisationController ✅ (already applied)
  • Return structured { statusCode, message } on 400/404 (NestJS default) ✅
  • Catch BA errors in addMember and map to 409 for duplicate member 📌
  • removeMember should be orgadmin-only on BA plugin config 📌 verify server
  • Rate-limit add-member to prevent email enumeration 📌
